# 段階ごとの公開(過去の版を、そのまま遊べるようにする)

発信(X・note)で、「あの投稿の時点のゲーム」を、あとからでも遊べるようにするための決まりです。

## しくみ

| 種類 | アドレス | 中身 |
|---|---|---|
| 最新版 | https://dobon-game.pages.dev/ | いつも最新(`main` ブランチ。PRをマージすると更新される) |
| 過去の段階 | `https://ブランチ名.dobon-game.pages.dev/` | その段階を終えたときの状態のまま、変わらない |

- 段階を終えるとき、そのときの `main` から、段階の名前のブランチ(コードの枝)を作ります
- Cloudflare Pages が、ブランチごとに専用のアドレス(`ブランチ名.プロジェクト名.pages.dev`)を自動で作ります
- **そのブランチには、あとから何も書き足さない**ので、アドレスの中身はずっと同じです
- アドレスが違うと、ホーム画面のアプリ(PWA)も、別のアプリとして扱われます。段階ごとに入れられます

## 段階とブランチ名

ブランチ名が、そのままアドレスになります。**投稿でアドレスを出したあとは、変えられません。**

| 段階 | ブランチ名 | アドレス | 状態 |
|---|---|---|---|
| ① ミニマム版 | `minimum` | https://minimum.dobon-game.pages.dev/ | 公開ずみ(2026-11-16。PWAまで入った状態) |
| ② ミニマム改良版 | `minimum-plus` | https://minimum-plus.dobon-game.pages.dev/ | これから |
| ③ ベーシック版 | `basic` | https://basic.dobon-game.pages.dev/ | これから |
| ④ ベーシック改良版 | `basic-plus` | https://basic-plus.dobon-game.pages.dev/ | これから |
| ⑤ UI改良版 | `ui-plus` | https://ui-plus.dobon-game.pages.dev/ | これから |
| ⑥ 海賊UI版 | `pirate-ui` | https://pirate-ui.dobon-game.pages.dev/ | これから |

名前を足す・変えるときは、この表も直します。ブランチ名は、小文字の英数字とハイフンだけにします(アドレスの一部になるため)。

## 段階を終えるときの手順

1. カイさんが Claude に「② ミニマム改良版を公開して」のように頼む
2. Claude が、`main` の最新から、その段階のブランチを作る(例:`minimum-plus`)
3. Cloudflare が自動でビルドする(1〜3分)
4. カイさんが、スマホで `https://ブランチ名.dobon-game.pages.dev/` を開いて、遊べることを確認する
5. この文書の表を、「公開ずみ」に直す(Claude がPRを出す)
6. 投稿に、そのアドレスを書く

> 作る前に、`main` に入れたい変更(次の段階の準備など)が混ざっていないか、確認します。作った瞬間の `main` が、その段階の内容になります。

## 守ること

- **段階のブランチには、push しない・消さない**(Claude も、人も)。書き足すと、アドレスの中身が変わってしまいます
- 次の段階の作業は、これまでどおり、作業用のブランチ → PR → `main` で進める
- Cloudflare の「デプロイ」一覧で、段階のデプロイを削除しない(削除すると、その版が開けなくなります)
- 古い版のバグは、直さない(直すと、「当時のゲーム」ではなくなります)。直したいときは、最新版で直す

## 誤って消さないための保護(GitHub の設定。任意)

スマホのブラウザで、GitHub のリポジトリを開いて設定します。画面の名前は、変わることがあります。

1. リポジトリの「Settings」→「Rules」→「Rulesets」→「New ruleset」→「New branch ruleset」
2. 名前を「stages」にして、Enforcement を「Active」にする
3. 「Target branches」→「Add target」→「Include by pattern」に、段階のブランチ名を入れる(`minimum`、`minimum-plus` など。いくつか追加する)
4. ルールのうち「Restrict deletions」(削除を禁止)と「Block force pushes」(強制の上書きを禁止)にチェックを入れる
5. 「Create」

> 段階が増えるたびに、パターンを足します。まとめて指定する場合は、`minimum*` `basic*` `ui-plus` `pirate-ui` のように書けます。

## うまくいかないとき

| 症状 | まずやること |
|---|---|
| 段階のアドレスを開くと「見つかりません」と出る | Cloudflare の「デプロイ」→「プレビュー(Preview)」に、そのブランチのビルドがあるか見る。ビルド中なら待つ。失敗していたら、ログのスクショを Claude に送る |
| ブランチを作ったのにビルドされない | Cloudflare のプロジェクトの「設定」→「ビルド」→「Branch control」で、プレビューのブランチが「すべての非本番ブランチ」になっているか確認する |
| アドレスが変わってしまった | 段階のブランチに、あとから push していないか確認する。ブランチ名を変えるとアドレスが変わる |
