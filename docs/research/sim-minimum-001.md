# シミュレーション結果:ミニマムルール(CPU4人・1000ゲーム)

> `npm run sim` で、同じ結果を作り直せます(シード 1〜1000)。CPUの考えは `docs/mvp/spec.md` 7節のとおり(出せるカードはランダム、張れるなら必ず張る、ドボンできるなら必ずドボン、チョンボはしない)。
> 時間(待ち時間・受付の長さ)は扱っていません。順番だけを再現しています。

## 1. 終わり方

| 終わり方 | ゲーム数 | 割合 |
|---|---|---|
| ドボン | 976 | 97.6% |
| チョンボ | 0 | 0.0% |
| 引き分け(山札なし) | 24 | 2.4% |
| 合計 | 1000 | 100% |

- チョンボは、CPUが「合計が合うときだけドボンする」ので、0になります(人間がミスしたときだけ起きます)
- 全ゲームが、エラーも止まりもなく終わりました

## 2. ゲームの長さ

| 項目 | 値 |
|---|---|
| 1ゲームの平均ターン数(全体) | 19.5 |
| 分布(全体) | 最小 1 / 中央値 15 / 90% 43 / 最大 78 |
| ドボンで終わったゲームの平均ターン数 | 18.4 |
| 引き分けで終わったゲームの平均ターン数 | 65.6 |

- ターン数は、始まったターンの数です(1周 = 4ターン)

## 3. 手札の最大枚数(ゲーム中に、誰かが持った最大)

| 項目 | 値 |
|---|---|
| 全ゲームでの最大 | 8枚 |
| 1ゲームごとの最大の平均 | 4.5枚 |
| 分布 | 最小 3 / 中央値 4 / 90% 6 / 最大 8 |

| 最大枚数 | ゲーム数 | 割合 |
|---|---|---|
| 3枚 | 119 | 11.9% |
| 4枚 | 434 | 43.4% |
| 5枚 | 308 | 30.8% |
| 6枚 | 108 | 10.8% |
| 7枚 | 28 | 2.8% |
| 8枚 | 3 | 0.3% |

- 画面の手札は「8枚までは広め、9〜14枚は自動で詰める、15枚以上は横スクロール」の想定です(spec.md 4-5)

## 4. 張りまわり

| 項目 | 値 |
|---|---|
| 初張りが1人以上いたゲーム | 451 / 1000(45.1%) |
| 1ゲームあたりの初張りの人数(平均) | 0.54 |
| 自動解除(合計14以上)が起きた回数 | 1579(1ゲームあたり 1.58) |
| 継続(still armed)が起きた回数 | 4302(1ゲームあたり 4.30) |

## 5. 席ごとの勝ち・負け(ドボンで終わった 976 ゲームのうち)

| 席 | 勝者になった回数 | 敗者になった回数 |
|---|---|---|
| 0(自分の席) | 245 | 225 |
| 1(左) | 258 | 251 |
| 2(上) | 217 | 260 |
| 3(右) | 256 | 240 |

- 席による大きな偏りがないかを見るための表です。親は毎回ランダムです

## 6. 読み方のメモ

- この結果は「CPUだけ・待ち時間なし」です。人間は、張る・ドボンの判断が遅かったり、ミスしたりするので、実際の割合とは変わります
- 試遊で気になった点(引き分けが多い、ゲームが長い・短いなど)は、この数字と比べて、パラメータやCPUの考えを調整します
