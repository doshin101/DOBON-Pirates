# ドボン MVP仕様書:一人プレイ(CPU3人と対戦)v0.1

作成日:2026-11-15

> ミニマムルールで、人間1人とCPU3人が1ゲーム遊べるスマホ向けWebゲームを作るための仕様です。
> **ルールの正は `docs/rules/minimum.md`** です。この文書は、ルールを画面と時間の流れで動かすための決めごとです。ルールとこの文書が食い違って見えるときは、ルールを優先し、カイさんに報告してください。
> 元になった設計書(Claudeプロジェクト側):`docs/design/turn-flow.md` v0.10、`docs/design/ui-effects.md` v0.13、`docs/design/system.md` v0.2

---

## 1. MVPのねらい

1. ミニマムルールが、画面上で正しく・気持ちよく動くことを確かめる
2. スマホだけで「指示 → 公開 → 遊んで確認」を回す開発の流れを作る
3. 発信(X・note)に使える「最初に動いたドボン」を作る

見た目は**最低限のワイヤーフレーム**でよい。演出は次の段階で作り込む。

## 3. 席と順番

- 自分は画面の下。CPUは左・上・右に座る
- 時計回り = **自分(下)→ 左 → 上 → 右 → 自分**
- 席の番号:0 = 自分、1 = 左、2 = 上、3 = 右。次のプレイヤーは `(番号 + 1) % 4`
- CPUの名前は仮で「CPU 1(左)」「CPU 2(上)」「CPU 3(右)」
- 親はランダム(シード付きの乱数で決める)

## 4. 進行の流れ

### 4-1. ゲーム開始時

1. シャッフルして、親から時計回りに3枚ずつ配る。山札の一番上をめくって**最初の場札**にする(山札の残りは39枚)
2. **開始時の受付**を `START_WINDOW_MS` の間行う。画面に「ゲーム開始まで 3…」のカウントダウンを出す
   - 手札の合計が13以下の人は**初張り**できる。押した時点の合計で確定する
   - CPUは、合計が13以下なら、配られてから `CPU_FIRST_ARM_DELAY_MS` のあとに必ず初張りする
   - 誰かが初張りしたら「○○が張った!」と表示する。残り時間が `FIRST_ARM_GRACE_MS` より短ければ、`FIRST_ARM_GRACE_MS` まで延ばす
   - 初ドボンはない(最初の場札はドボンの対象外)
3. 開始時の受付が終わったら、親のターンを始める。以後、初張りはできない

> 原本の turn-flow 8節にある「他に初張りできる人がいなければ猶予を飛ばす」は、MVPでは行わない(手札の情報が漏れるのを避けるため、時間は一定にする)。

### 4-2. ターンの段階

| 段階 | 名前 | MVPでの扱い |
|---|---|---|
| ① | ターン開始 | 「○○の番」を表示する。`TURN_START_MS` |
| ② | 操作待機 | 最初の操作(プレイかドロー)を実行するまで。**人間は時間無制限**。CPUは `CPU_THINK_MS` のあとに実行 |
| ③ | 操作中 | ドローのあと、プレイかパスを実行するまで。人間は時間無制限。CPUは `CPU_THINK_MS` のあとに実行 |
| ④ | 受付中 | 操作完了の直後。プレイのときは `ACCEPT_MIN_MS`、パスのときは `PASS_PAUSE_MS` |
| ⑤ | ターン終了 | 継続のテロップを出す。次のプレイヤーの①へ |

- 最初の操作がプレイのときは③を通らない
- **人間の②の操作ボタンは、前のターンの④が終わってから押せる**(④は前のプレイヤーのターンの一部なので)。そのため、どのカードにも最低 `ACCEPT_MIN_MS` のドボン受付が保証される

### 4-3. 操作の選択肢(M-2)

手番のプレイヤーが押せるボタンは、状況で決まる。押せないボタンは非活性にし、理由を短く出す。

| 場面 | 状況 | プレイ | ドロー | パス |
|---|---|---|---|---|
| ② | 手札2枚以上・出せるカードあり | ○ | ×「出せるカードがあります」 | ×「ドローの後だけ」 |
| ② | 手札2枚以上・出せるカードなし | ×「出せるカードがありません」 | ○ | ×「ドローの後だけ」 |
| ② | 手札1枚 | ×「手札が1枚のときは先にドロー」 | ○ | ×「ドローの後だけ」 |
| ③ | 出せるカードあり | ○ | ×「ドローは1回だけ」 | ×「出せるカードがあります」 |
| ③ | 出せるカードなし | ×「出せるカードがありません」 | ×「ドローは1回だけ」 | ○ |

- プレイボタンは、出せるカードを1枚選んでいるときだけ押せる
- 出せるカード = 場札と**同じ数字か同じマーク**

### 4-4. カードの選択(ui-effects E-15)

- カードをタップで選択(少し持ち上げる)、もう一度タップで解除。**選択は操作の実行ではない**(②のまま。受付も閉じない)
- 出せないカードは非活性。非活性は2種類で、見た目を変える
  - **そもそも出せないカード**:暗くする
  - **他のカードを選んだために選べないカード**:薄く点線の枠にする(解除すれば選べると分かるように)
- 1枚選んでいる間は、他のカードは選べない(選び直すときは、解除してから)
- 自分の番でないときは、カードは選べない

### 4-5. 手札の表示(ui-effects E-11)

- 手札の枚数が変わったときに、自動で並び替える。並びは**右端から「スペード → クラブ → ハート → ダイヤ」**、各マークの中は数字の昇順(つまり左から:ダイヤ昇順、ハート昇順、クラブ昇順、スペード昇順)
- 枚数が増えたら重なりを詰める。目安:8枚までは広め、9〜14枚は自動で詰める、15枚以上は横スクロール
- **手札の合計は、自分にだけ常に数字で表示する**
- 他の3人は、カードの束と枚数だけを表示する

## 5. 張り(M-3)

### 5-1. 張りボタン(ui-effects E-01・E-05)

- 張りとドボンは、**1つのメインボタン**で扱う。張っていないときは「張る」、張ったあとは「ドボン」に変わる
- 「張る」を押せるのは、次の両方を満たすとき
  - 手札の合計が13以下
  - 開始時の受付中、または自分のターンの②③④
- 押せないときは非活性にし、理由を短く出す(「合計が14以上」「自分のターンのみ」)
- **②③で押したときは仮押し**:「張る(予約中)」と表示し、操作完了の時点の合計で決まる
  - 13以下 → 張り確定(「張りました」)
  - 14以上 → 失敗(「張れませんでした(合計○)」)
- **④で押したときは、押した時点の合計で確定する**
- 張りの取り消しはできない(仮押しも取り消せない)

### 5-2. 自動解除と張り直し

- 張っている人の操作完了の時点で、合計が14以上なら自動で解除する。「○○の張りが外れた」と表示する
- 解除されたあと、合計が13以下に戻っても、自動では張り直さない。もう一度押す必要がある

### 5-3. 継続のテロップ(ui-effects E-04・E-10)

- 張った状態で自分のターンを始め、ターンの終了(⑤)でも張っていたら、「○○ 継続」のテロップを1秒ほど出す
- MVPでは文字だけ。人ごとに出す

### 5-4. 公開

- 張っている人には、名前の横に「張り」のバッジを付ける。全員から見える

## 6. ドボン(M-4・M-5)

### 6-1. ドボン受付

- 始まり:カードがプレイされた直後(④の開始)
- 終わり:次のどちらか早い方
  - 次のプレイヤーが最初の操作(プレイかドロー)を実行したとき
  - ドボンの宣言があってから `GRACE_MS` が過ぎたとき
- パスのときは場札が変わらないので、受付はない
- 受付は場札1枚につき1回だけ
- 受付中は、場札の周りに「ドボン受付中」の枠を出す。①で次の人の番の表示に変わっても、枠は残す

### 6-2. ドボンボタン(ui-effects E-06)

- 張っていない人には表示しない(張りボタンのまま)
- 場札が**最初の場札**か**自分がプレイしたカード**のときは、ドボンボタンを非活性にし、「対象外」と出す(操作を受け付けない)
- 張っていて、場札が他の人のカードなら、ドボンボタンを表示する
- ドボンは、ボタンに触れた指を**上に約48px動かした時点**で発火する(指を離すときではない)。タップだけでは発火しない。PCではマウスのドラッグでも同じように動く
- 受付中は、**合計が合っていなくてもフリックできる**(チョンボの可能性を残す)
- 受付の時間外はグレー表示。フリックしても無効(何も起きない。チョンボにもならない)
- 1回の受付で、宣言は1人1回まで。宣言したら、自分の画面に「判定待ち…」を出す

### 6-3. 猶予と判定

- 誰か(人間でもCPUでも)がドボンを宣言したら、`GRACE_MS` の猶予を始める。猶予の間に宣言された分も、同じ判定に含める
- 猶予の間は、次のプレイヤーの操作を止める(人間なら操作ボタンを「判定中」で非活性、CPUなら待つ)
- **判定までは、誰が宣言したかを他の人に見せない**(宣言した本人にだけ「判定待ち」)
- 判定のしかた
  1. 宣言のうち、**張っていて、合計 = 場札の数字**のものが「有効なドボン」
  2. 有効なドボンがあれば、プレイした人から時計回りで次のターンに近い人が**勝者**、プレイした人が**敗者**。チョンボは取らない
  3. 有効なドボンがなく、合計が合わない宣言(チョンボ)があれば、チョンボした全員が**敗者**(勝者なし)
  4. 宣言がなければ、何も起きずに受付を閉じる
- 判定が出たら、画面中央に大きく「ドボン!」または「チョンボ!」と名前を出し(`RESULT_FLASH_MS`)、結果画面へ進む

### 6-4. 山札がなくなったとき(M-6)

- ドローが必要な場面(手札1枚のとき、または出せるカードがないとき)で山札が0枚なら、引き分けにする
- ただし、その時点で受付中・猶予中なら、**先に判定する**。ドボンかチョンボが成立したら、そちらが結果になる
- 人間の番なら、ドローボタンを押した時点でこの処理をする。CPUの番なら、ドローを実行しようとした時点で行う

## 7. CPUの動き(system.md 6節)

- 見てよい情報は、人間と同じ(公開情報と自分の手札だけ)。他の人の手札や山札の順番は見ない
- 手番の操作:出せるカードがあれば、その中から**ランダム**に1枚プレイ。なければドロー。ドローのあと、出せればランダムにプレイ、なければパス。手札1枚ならまずドロー
- 張り:**条件を満たしたら必ず張る**
  - 開始時:合計13以下なら初張り(4-1)
  - 自分のターン:操作完了の直後(④の始め)に、張っておらず合計13以下なら張る
- ドボン:張っていて、他の人がプレイした場札の数字が自分の合計と一致したら、**必ず宣言する**。宣言するのは、受付が始まってから `CPU_DOBON_REACTION_MS` のあと(必ず `ACCEPT_MIN_MS` より短い)
- CPUはチョンボしない
- 難易度はない。ただし、あとで難易度を足せるように、CPUの考えるところは1つの関数(`decide`)にまとめる
- 乱数はシード付きで、同じシードなら同じ展開になること

## 8. パラメータ(初期値)

すべて1か所(`packages/core/src/params.ts` など)にまとめ、あとで変えられるようにする。値は試遊で調整する。

| 名前 | 内容 | 初期値 |
|---|---|---|
| `START_WINDOW_MS` | 開始時の受付の長さ | 4000 |
| `FIRST_ARM_GRACE_MS` | 初張りのあと、最低限残す時間 | 1500 |
| `CPU_FIRST_ARM_DELAY_MS` | CPUが初張りするまで | 600〜1500(ランダム) |
| `TURN_START_MS` | ①の表示 | 400 |
| `CPU_THINK_MS` | CPUが操作するまで | 700〜1200(ランダム) |
| `ACCEPT_MIN_MS` | プレイのあとの④の長さ(ドボン受付の最低時間) | 2500 |
| `PASS_PAUSE_MS` | パスのあとの④の長さ | 600 |
| `CPU_DOBON_REACTION_MS` | CPUがドボンを宣言するまで | 400〜1200(ランダム) |
| `GRACE_MS` | 猶予 | 1000 |
| `STILL_ARMED_TOAST_MS` | 継続のテロップ | 1000 |
| `RESULT_FLASH_MS` | 「ドボン!」の表示 | 1800 |

デバッグの速さ(×1 / ×2 / ×4)を選ぶと、すべての時間をその倍率で割る。

## 9. 作りの決まり

### 9-1. 構成

| 場所 | 役割 |
|---|---|
| `packages/core` | ルールの判定と、ゲームの状態の変化。**画面・時間・本物の乱数を使わない**(乱数はシード付きのものを外から渡す)。CPU・サーバー・テストで使い回す |
| `packages/cpu` | CPUの考え(`decide`)。公開情報と自分の手札だけを受け取る |
| `packages/i18n` | 言語ファイル(`ja.json`、`en.json`) |
| `apps/web` | 画面。時間の管理(タイマー)もここ。core に「操作」を渡して、新しい状態を受け取って表示する |

- 状態の変化は「今の状態 + 操作 → 新しい状態 + 起きたこと(イベント)」の形にする。イベントは、ログや将来の演出に使う
- 時間の管理(タイマー)は、テストで時間を早送りできる作りにする

### 9-2. 自動テストで確かめること

| # | 確かめること |
|---|---|
| T-01 | 配り終わったとき:52枚がそろっている、各3枚、最初の場札1枚、山札39枚 |
| T-02 | 出せるカード:同じ数字か同じマークだけ |
| T-03 | 手札2枚以上で出せるカードがあるときは、ドローできない |
| T-04 | 手札1枚のときは、プレイできず、先にドロー |
| T-05 | パスはドローの後で、出せるカードがないときだけ |
| T-06 | 仮押し:操作完了の合計13以下で確定、14以上で失敗 |
| T-07 | 張っている人の操作完了の合計が14以上なら自動解除。そのあと13以下になっても張り直されない |
| T-08 | ④の張りは、押した時点の合計で決まる |
| T-09 | 張っていない人は、ドボンできない |
| T-10 | 最初の場札・自分がプレイしたカードには、ドボンできない(受け付けない) |
| T-11 | 受付の時間外のドボンは無効(チョンボにならない) |
| T-12 | 張っていて合計が一致 → ドボン成立。勝者と敗者が正しい |
| T-13 | 複数人のドボン → プレイした人から時計回りで近い人が勝者 |
| T-14 | ドボンとチョンボが重なったら、ドボンが優先 |
| T-15 | 複数のチョンボ → 全員が敗者 |
| T-16 | 受付は、次のプレイヤーの最初の操作の実行で閉じる。カードを選んだだけでは閉じない |
| T-17 | パスでは受付が始まらない |
| T-18 | ドローして合計が場札と一致しても、ドボンできない |
| T-19 | 次のプレイヤーが②で仮押ししても、受付中のカードにはドボンできない |
| T-20 | 山札が0枚でドローが必要 → 先に判定し、成立しなければ引き分け |
| T-21 | 手札1枚・山札0枚 → その1枚が出せるカードでも引き分け |
| T-22 | 同じシードなら、CPUだけの対戦が同じ展開になる |
| T-23 | CPUだけで1000ゲーム回しても、エラーや止まりが起きない(必ずドボン・チョンボ・引き分けのどれかで終わる) |

## 10. 画面

ワイヤーフレーム `docs/mvp/wireframe.html` を正とする。要点だけ書く。

| 画面 | 内容 |
|---|---|
| ホーム | タイトル、「CPUと対戦」ボタン、「ルール」(ミニマムルールの要約)、デバッグの設定(小さく) |
| 対戦 | 上:山札の残り・メニュー。左上右:CPU(名前、手札の束と枚数、張りバッジ、手番の印)。中央:場札(プレイした人の名前 / 「最初の場札」)、受付中の枠、メッセージ。下:自分の手札、合計、メインボタン(張る/ドボン)、プレイ・ドロー・パス。一番下:折りたたみのログ |
| 結果 | 「ドボン!」「チョンボ!」「引き分け」、勝者・敗者・どちらでもない、理由、最後の場札、全員の手札(合計つき)、「もう一度」「ホームへ」 |

- スマホの縦持ち(幅360〜430px)を基本にする。PCでは中央に同じ幅で表示する
- 指で押すところは、最低44px角
- 色は白黒グレー + 強調色1色でよい

### デバッグ(URLに `?debug=1` を付けたとき、またはホームの設定)

- シードの指定(`?seed=123`)。結果画面にシードを出し、同じ展開を再現できるようにする
- CPUの手札を表で表示する
- 進行の速さ ×1 / ×2 / ×4
- ログを最初から開いておく
