# ドボン MVP の進め方(マイルストーンと指示文)

> Claude Code に、1つずつ順番に頼みます。**1マイルストーン = 1回の依頼 = 1つのPR(プルリクエスト)** が目安です。
> 各マイルストーンの「指示文」を、そのまま Claude アプリの Code タブに貼り付けてください。
> 終わったら、Cloudflare のプレビューURLをスマホで開いて「確認すること」をチェックし、問題なければPRをマージします。

---

## M0. 土台づくり(画面に「DOBON」と出るだけ)

**指示文**

```
CLAUDE.md と docs/mvp/spec.md を読んでから作業してください。
マイルストーン M0(土台づくり)をお願いします。

- CLAUDE.md 5節のフォルダ構成で、npm workspaces のひな形を作る(apps/web、packages/core、packages/cpu、packages/i18n)
- apps/web は Vite + React + TypeScript。ホーム画面に「DOBON」と「CPUと対戦」ボタン(押しても何も起きなくてよい)を出す。文字は packages/i18n の ja.json から出す
- packages/core にダミーの関数とテストを1つ置き、npm test が動くようにする
- ルートの npm run build で apps/web/dist に出力されるようにする(Cloudflare Pages 用)
- .nvmrc に Node のバージョンを書く
- README.md に、このリポジトリの説明と Cloudflare Pages の設定値を書く

終わったら PR を出し、スマホで確認することを教えてください。
```

**スマホで確認すること**

M0 だけは、プレビューではなく次の順で確認します(Cloudflare の設定がまだないため)。

- [ ] PR の説明に「テストとビルドが通った」と書いてある → そのままマージする
- [ ] `docs/setup/smartphone-workflow.md` の「B. Cloudflare Pages の設定」をする
- [ ] 本番のURL(`〇〇.pages.dev`)を開くと「DOBON」と「CPUと対戦」が出る
- [ ] M1 以降は、PR ごとにプレビューURLが出るようになる

## M1. ルールの中身(画面なし)

**指示文**

```
CLAUDE.md、docs/rules/minimum.md、docs/mvp/spec.md を読んでから作業してください。
マイルストーン M1(ルールエンジン)をお願いします。画面は作りません。

- packages/core に、ミニマムルールのゲームの状態と操作を作る(spec.md 4〜6節、9節)
  - 配る、操作の選択肢、プレイ・ドロー・パス、張り(仮押し・確定・自動解除)、ドボン受付、ドボンとチョンボの宣言、判定、引き分け
  - 時間は扱わない。「受付を閉じる」「猶予が終わった」なども、外から渡す操作にする
  - 乱数はシード付きのものを外から渡す
- packages/cpu に、spec.md 7節の CPU の考え(decide)を作る
- spec.md 9-2 のテスト T-01〜T-23 をすべて書いて、通す
- CPUだけで1000ゲーム回して、ドボン・チョンボ・引き分けの割合、1ゲームの平均ターン数、手札の最大枚数を docs/research/sim-minimum-001.md にまとめる

仕様で分からないところがあれば、作り始める前に質問してください。
```

**スマホで確認すること**

- [ ] PRの説明に「テストがすべて通った」と書いてある
- [ ] `docs/research/sim-minimum-001.md` の数字を読んで、感覚と合っているか(引き分けが多すぎない?など)

## M2. 対戦画面(張り・ドボンなし)

**指示文**

```
CLAUDE.md、docs/mvp/spec.md、docs/mvp/wireframe.html を読んでから作業してください。
マイルストーン M2(対戦画面の基本)をお願いします。

- ワイヤーフレームの ③ のとおり、対戦画面を作る(CPUの席、場札、山札の残り、手札、合計、プレイ・ドロー・パス)
- 「CPUと対戦」で対戦画面に進み、M1 の core と cpu を使って、自分とCPU3人が順番にプレイできるようにする
- カードの選択(タップで選択・解除、非活性2種類)、操作できない理由の表示(spec.md 4-3、4-4)
- 手札の自動並び替え(4-5)
- CPUの待ち時間、①④の時間など、タイマーの仕組み(spec.md 4-2、8節)。速さの倍率を変えられる作りにする
- 画面下に折りたたみのログ
- この段階では、張りとドボンのボタンは表示だけ(押しても何も起きない)。ゲームは山札がなくなって引き分けで終わる。終わったら「引き分け」とだけ出す
```

**スマホで確認すること**

- [ ] 自分の番でカードを選んで出せる。選択を解除できる
- [ ] 出せないカードが灰色、他を選んだせいで選べないカードが点線になる
- [ ] 出せるカードがあるのにドローしようとすると、理由が出る
- [ ] 手札が1枚のとき、先にドローになる
- [ ] CPUが少し間を置いて動く
- [ ] 最後に引き分けになる

## M3. 張りとドボン(ゲームとして完成)

**指示文**

```
CLAUDE.md、docs/mvp/spec.md、docs/mvp/wireframe.html を読んでから作業してください。
マイルストーン M3(張りとドボン)をお願いします。

- メインボタン(張る / ドボン)を、wireframe.html の下の表のとおりに動かす(spec.md 5節、6節)
  - 張る:タップ。②③は仮押し、④はすぐ確定。押せない理由を出す
  - ドボン:上に約48px動かした時点で発火する上フリック。PCではマウスのドラッグでも動く
- ドボン受付中の枠、張りバッジ、判定待ち、猶予、判定、「ドボン!」「チョンボ!」の表示(ワイヤーフレーム ④ ⑤)
- CPUの張りとドボン(spec.md 7節)
- 自動解除と、継続のテロップ
- ゲーム開始時の受付(初張り、カウントダウン。ワイヤーフレーム ②)
- 結果画面(ワイヤーフレーム ⑥)と「もう一度」「ホームへ」
```

**スマホで確認すること**

- [ ] 合計13以下で「張る」が押せる。14以上では理由が出て押せない
- [ ] 自分の番の途中で押すと「予約中」になり、出したあとの合計で確定・失敗が分かる
- [ ] CPUのカードに上フリックでドボンでき、勝てる
- [ ] 合計が合わないのにフリックすると、チョンボで負ける
- [ ] タップしただけではドボンにならない
- [ ] 自分が出したカードで、CPUにドボンされることがある
- [ ] 結果画面で全員の手札と合計が見える。「もう一度」で次のゲームが始まる

**指示文**

```
CLAUDE.md と docs/mvp/spec.md を読んでから作業してください。
マイルストーン M4(デバッグと仕上げ)をお願いします。

- spec.md 10節のデバッグ機能(?debug=1、?seed=、CPUの手札表示、速さ×1/×2/×4、結果画面のシード表示)
- ホームの「ルール」画面(ミニマムルールの要約。言語ファイル経由)
- spec.md 11節の完成の条件を確かめ、満たしていないものを直す
- 自分がドボンで勝つ・ドボンされて負ける・チョンボ・引き分けを再現できるシードを探して、docs/mvp/test-seeds.md に「シードと、どう操作すればその結果になるか」を書く
- en.json に英語の文字を入れる(画面の言語の切り替えはまだ作らなくてよい)
```

**スマホで確認すること**

- [ ] `test-seeds.md` のシードで、4つの終わり方を自分で再現できる
- [ ] 速さ×4で、すばやく1ゲームを見られる
- [ ] 縦持ちで、ボタンが押しやすい(小さすぎない)

## そのあと(MVPの後の候補)

- 試遊でパラメータを調整する(受付時間、猶予など)
- 演出の作り込み(「ドボン!」の溜め、音、振動の代わりの光)
- PWA化(ホーム画面に追加できる)
- 張り中の手札を裏向きにする(E-03)
- ベーシックルール(ポイント・精算)
