# 0003 M1 ルールエンジンの作り方

決めた日:2026-11-15 / 決めた人:Claude Code(M1 作業中の小さな判断)

仕様(spec.md・minimum.md)に書いていない、実装上の細かい決めごとです。画面の見え方やルールは変えていません。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 配り方 | 親から時計回りに、**3枚ずつまとめて**配る(1人3枚 → 次の人) | spec 4-1「3枚ずつ配る」の文字どおり。ルールには影響しない(配りの順番は、シードの再現にだけ関わる) |
| 乱数の使い方 | `createGame(rng)` に外から渡す。親を決める → シャッフル、の順に使う | CLAUDE.md 6節。同じシードなら同じ配りになる。乱数の実体は mulberry32(外部ライブラリなし) |
| 山札の向き | 配列の先頭(index 0)が、次にドローされるカード | 実装を単純にするため |
| 時間に関わる操作 | 外から渡す操作にした:`endStartWindow`(開始時の受付が終わった)、`endTurn`(④が終わり、ターンが終わる)、`resolve`(猶予が終わった) | M1 の指示「時間は扱わない」。画面側のタイマーが、時間が来たらこれらを渡す |
| ①ターン開始 | core では ② `awaitAction` に含める(「①だけの段階」は持たない) | ①は画面の表示時間(400ms)だけで、ルールの上の違いがない。画面側が①の間は押せないようにする |
| 受付が閉じるとき | 次のプレイヤーの最初の操作(プレイかドロー)を実行したとき | minimum.md M-4 |
| 判定待ちの扱い | 宣言があるとき、次のプレイヤーのプレイ・ドローは `resolutionPending` で受け付けない。ただし**山札0枚のドロー**は、その場で先に判定して終わらせる | spec 6-3、6-4(T-20) |
| 宣言したあとの判定 | 宣言が1つでもあれば、`resolve` で必ず「ドボン」か「チョンボ」のどちらかで終わる | 受付中は、張りの人の入れ替わりが起きないため(宣言は、張っている人しかできない) |
| 受付の時間外のドボン | エラーにはせず、`dobonVoid` のイベントを返して状態は変えない(無効・ノーカウント) | minimum.md M-4「操作はできるが無効」。ただし、張っていない・自分のカード・最初の場札は、そもそも受け付けない(エラー) |
| 操作できない理由 | 日本語ではなく、名前(`hasPlayableCard` など)で返す。画面の文字は i18n から選ぶ | CLAUDE.md 4節 |
| CPUの `decide` | 「いまやりたいこと」(ドボン/張る/プレイ/ドロー/パス/何もしない)を1つ返す。優先順位は ドボン > 張り > 手番の操作。**待ち時間は返さない**(呼ぶ側が決める) | 時間を core・cpu に入れないため。M2 以降、画面のタイマーが `CPU_THINK_MS` などを使って呼ぶ |
| CPUに渡す情報 | `PlayerView`(自分の手札、全員の枚数、張りの公開、場札、場札をプレイした人 など)。他の人の手札・山札・他の人の宣言と仮押しは含めない | spec 7節「ズルをしない」 |
| シミュレーション | `packages/cpu/src/simulate.ts`。集計は `npm run sim`(`vite-node` を使う。Vitest に付いてくるので、新しいライブラリは足していない) | M1 の指示 |
| `params.ts`(時間のパラメータ) | **M1 では作らない**(M2 で `packages/core/src/params.ts` に作った。0004 参照) | M1 は時間を扱わないため |
| 型チェック | `npm run build` の最初に、全パッケージの型チェックを実行する | テストの書き間違いも、公開前に見つけるため |

## ほかの案

- 配りを「1枚ずつ3周」にする → ルールに差はない。シードの展開は変わる。あとで変えたくなったら、`createGame` だけ直せばよい(ただし M4 の `test-seeds.md` を作ったあとは、シードが変わるので注意)
- ①を core の段階として持つ → 段階が増えるだけで、ルールに効かないので見送り
- `decide` が待ち時間も返す → 時間を core 側に持ち込むことになるので見送り
