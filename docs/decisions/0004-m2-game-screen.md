# 0004 M2 対戦画面の作り方

決めた日:2026-11-15 / 決めた人:Claude Code(M2 作業中の小さな判断)

仕様(spec.md・wireframe.html)に書いていない、細かい決めごとです。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 時間のパラメータの置き場 | `packages/core/src/params.ts`(spec 8節の全項目を入れた。M2 で使うのは `TURN_START_MS`・`CPU_THINK_MS`・`ACCEPT_MIN_MS`・`PASS_PAUSE_MS`) | spec 8節の例どおり。core は数字を持つだけで、時間は数えない(数えるのは画面側のタイマー) |
| タイマーの作り | `apps/web/src/game/GameRunner.ts`。時計(`Scheduler`)を外から渡せる。テストでは偽の時計で時間を早送りする | spec 9-1「テストで時間を早送りできる作り」 |
| 速さの倍率 | `GameRunner` が `speed` を受け取り、すべての待ち時間を割る。**画面からの切り替えは M4**(M2 は ×1 固定) | M2 の指示は「変えられる作りにする」まで |
| 待ち時間の乱数 | CPUの選択に使う乱数とは別の乱数(シード+固定の数)を使う | 待ち時間が変わっても、同じシードなら同じ展開になるようにするため(テストあり) |
| 張り・ドボンの扱い | M2 では、CPUも張らない・ドボンしない。開始時の受付(初張り)も飛ばして、すぐ親のターンを始める。「張る」ボタンは core の判定どおりに表示するだけで、押しても何も起きない | M2 の指示。M3 で動かす |
| 「ドボン受付中」の枠 | M2 では出さない | ドボンできない段階で出すと混乱する。M3 の項目 |
| 終了画面 | 「引き分け」のほかに、「ホームへ」ボタンだけ付けた | 指示は「引き分けとだけ」だが、ボタンがないと行き止まりになるため。結果画面(全員の手札・もう一度)は M3 |
| ≡ メニュー | 押すと、確認(「対戦をやめて、ホームに戻りますか?」)のあと、ホームに戻る。ゲーム終了後は確認なし | ワイヤーフレームにある ≡ に何も機能がないと紛らわしいため。スマホで途中でやり直せる |
| シード | 対戦ごとにランダムに決める(画面側で `Math.random`)。`?seed=` での指定は M4 | spec 10節のデバッグ機能は M4 |
| 席の名前 | 「あなた」「CPU 1(左)」「CPU 2(上)」「CPU 3(右)」。親には「親」の印 | spec 3節の仮の名前。ワイヤーフレームの「あなた(親)」に合わせた |
| ターン開始①の間 | 人間のボタン・カードは押せない。理由は出さない | spec 4-2(①は表示だけ。すぐ②になる) |
| 手札の重なり | 8枚まで:1枚あたり40px(少し重なる)。9〜14枚:自動で縮む。15枚以上:24px固定で横スクロール | spec 4-5。9枚以上ではカードの一部しか見えなくなる(タップできる幅が44px未満になる)。見えにくければ M4 で調整 |
| 色 | 白・黒・グレー+オレンジ(ワイヤーフレームの強調色 `#e8590c`)。ハート・ダイヤも黒のまま(マークの形で区別) | spec 10節「色は白黒グレー+強調色1色」 |
| カードの記号(♠♥♦♣、A・J・Q・K) | これも `ja.json` に入れた | 「画面に出す文字は言語ファイル経由」 |
| 新しいライブラリ | なし | CLAUDE.md 4節 |

## ほかの案

- 開始時の受付を M2 から入れる → M3 の項目で、M2 ではCPUが張らないので意味がない
- 速さの倍率をいま URL(`?speed=4`)で変えられるようにする → M4 のデバッグ機能にまとめる
- 手札の重なりを、画面幅を測って JavaScript で計算する → CSS だけで足りたので見送り
