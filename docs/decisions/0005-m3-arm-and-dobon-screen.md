# 0005 M3 張りとドボンの画面の作り方

決めた日:2026-11-15 / 決めた人:Claude Code(M3 作業中の小さな判断)

仕様(spec.md 4〜6節・wireframe.html)に書いていない、細かい決めごとです。ルールは変えていません。

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 猶予の間の進み方 | 宣言があった時点で、ターンの進行のタイマー(④の残り・CPUの待ち・①の表示)を止める。猶予が終わると、必ず「ドボン」か「チョンボ」で終わる | spec 6-3「猶予の間は次のプレイヤーの操作を止める」。core の仕様(宣言があれば判定で必ず終わる)と合う |
| CPUのドボンの宣言 | カードがプレイされて受付が始まった時点で、ドボンできるCPUを決めて、`CPU_DOBON_REACTION_MS`(400〜1200ms)のあとに宣言する(受付の最低時間2500msより必ず短い) | spec 7節 |
| CPUの張り | 初張りは配ってから `CPU_FIRST_ARM_DELAY_MS`(600〜1500ms)のあと。自分のターンの操作完了の直後(④の始め)は、待たずにすぐ張る | spec 4-1、7節 |
| 初張りの延長 | 誰か(人間もCPUも)が初張りしたとき、残りが `FIRST_ARM_GRACE_MS`(1.5秒)より短ければ、1.5秒まで延ばす。それ以外は延ばさない | spec 4-1 |
| カウントダウン | 「ゲーム開始まで 4 → 3 → 2 → 1」(残り時間の切り上げ)。0 は出さない | wireframe ② は「3」の例。初期値4秒に合わせた |
| 「張る」を押せる時間 | 開始時の受付と、自分のターンの②③④。①(ターン開始の表示 400ms)は押せない | spec 5-1(core は①も②に含めるので、画面側で止めている) |
| ドボン受付の時間外のフリック | 画面側では何も送らない(何も起きない)。core の「無効(void)」の仕組みは、画面からは使わない | spec 6-2「フリックしても無効。何も起きない」。テストでは core 側で確認済み(T-11) |
| ドボンのフリックの作り | ポインタイベント(指・マウス共通)で、押した位置から上に48px動いた時点で発火。指を離すのを待たない。そのボタン上では画面がスクロールしないようにしている(`touch-action: none`) | spec 6-2 |
| 判定待ち中の表示 | 宣言した本人のメインボタンだけ「判定待ち…」。他の人には宣言したことを見せない。ただし、猶予の間に人間が次のプレイヤーなら、プレイ・ドロー・パスの理由は「判定中」と出る(仕様どおり) | spec 6-3 |
| ログ | CPUのドボンの宣言は、判定まで出さない(自分の宣言だけ出す)。ゲームが終わったら、最後に結果の行を足す | 「誰が宣言したかは判定まで見せない」 |
| 知らせ(トースト) | 「○○が張った!」「張りました」「張れませんでした(合計○)」「○○の張りが外れた」「○○ 継続」。最大3つまで同時に出る。継続は `STILL_ARMED_TOAST_MS`(1秒)、ほかは新しいパラメータ `TOAST_MS`(1.5秒) | spec 4-1、5節。長さは spec にないので、1.5秒とした |
| 「ドボン!」の表示 | ドボン・チョンボのときだけ、`RESULT_FLASH_MS`(1.8秒)出して結果画面へ。引き分けは、表示なしで結果画面へ | spec 6-3(「判定が出たら」ドボンかチョンボ) |
| 結果画面 | wireframe ⑥ のとおり。シード表示はデバッグ(M4)。引き分けの理由は「山札がなくなりました」 | spec 10節 |
| 「もう一度」 | 新しい配り(新しいシード)で、開始時の受付から始める | spec 11節。同じシードでの再現は M4 |
| ≡ メニュー | M2 のまま(確認のあと、ホームへ) | — |

## ほかの案

- 猶予の間もターンのタイマーを動かし続ける → 判定前に次のプレイヤーが操作してしまうので見送り
- 受付の時間外のフリックも core に送って「無効」を記録する → 画面側で止めるほうが単純。仕様の「何も起きない」と同じ
